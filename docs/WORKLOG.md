## 2026-11-09 · #7·#8 방송 스튜디오 (PC 화면 공유, 모바일 카메라, 시청 플레이어) (`feat/7-pc-studio`)

#7(PC 송출)과 #8(모바일 송출·시청)은 같은 송출 컨트롤러와 화면을 공유해서 한 브랜치로 진행했다. 소스만 화면 공유/카메라로 다르다.

### 설계 판단
| 결정 | 근거 | 확신 |
|---|---|---|
| 송출 상태 머신을 React 밖 `Publisher` 클래스로 분리, 화면은 `useSyncExternalStore`로 구독 | 재연결 루프·타이머·장치 정리가 렌더 주기와 얽히지 않는다. 전이를 한 파일에서 읽을 수 있다 | 85% |
| 별도 화면 `/broadcasts/:id/studio`, 상세의 "방송 시작하기"로 진입 | 시청 화면과 송출 화면의 관심사가 다르다(장치 권한, 이탈 경고). 시청 화면을 새 탭으로 열어 확인할 수 있다 | 85% |
| 끊김 시 3초 뒤 서버 상태를 보고 판단: ENDED→종료, LIVE(끊김 없음)→다른 곳에서 송출 중, 그 외→새 토큰으로 재송출(최대 5회) | 대체 송출(overridePublisher)은 이전 탭에 알려지지 않는다(#2 발견 2). 두 탭이 서로 송출을 빼앗는 핑퐁을 막는다 | 85% |
| 같은 브라우저 탭끼리는 BroadcastChannel로 즉시 알림 | 서버 확인(수 초)보다 빠르고 정확하다. 미지원 브라우저는 서버 확인으로 대체된다 | 85% |

### MediaMTX가 세그먼트 훅을 offline에 묶어 끝내는가 (리뷰 8)
- 끝내지 않는다. v1.21.3 `internal/core/path.go`의 `OnSegmentComplete`(https://github.com/bluenviron/mediamtx/blob/v1.21.3/internal/core/path.go#L1054-L1068)는 `externalcmd.Cmd{Restart: false}`를 만들어 `Start()`만 하고 path에 보관하지 않는다. path offline에서 정리하는 것은 `setOffline()`의 `onOfflineHook`(= `runOnOnline` 프로세스 종료, #7에서 확인한 현상)뿐이다. 따라서 훅은 송출 종료 후에도 끝까지 실행되고, 끊기는 경우는 mediamtx 프로세스 자체가 끝날 때(외부 명령 풀 종료)뿐이다 → 복구 스캔이 메운다.
- 실제 동작도 일치: E2E에서 훅은 항상 송출 종료(kick·탭 닫기) 뒤에 실행되어 변환·등록까지 끝났다.

### #29 후원 승인 멱등키·일시 오류 (PR #32)
- 멱등키를 `confirm-{orderId}-{confirm_attempt}`로(`confirmIdempotencyKey`, 마이그레이션 0006). 일시 오류(네트워크·429·5xx·응답 형식·`PROVIDER_ERROR`·처리 중 409)는 결제 조회로 실제 상태를 확인해 DONE이면 적립, 아니면 PENDING + 502. 일시 오류·결과 미정으로는 FAILED가 되지 않는다. 처리 중 409는 시도 번호를 올리지 않는다.
- 가짜 토스(`withFakeIdempotency`)가 멱등 캐시·처리 중 409·`ALREADY_PROCESSED_PAYMENT`를 흉내 낸다(E2E 가짜 결제에도 적용). 중복 적립 방어(조건부 UPDATE + 원장 order_id 유니크)는 그대로.
- API 테스트 371 → 393.

| 지적 | 처리 |
|---|---|
| [명세] 타임아웃 → 조회 IN_PROGRESS → 새 키 ALREADY_PROCESSED → VERIFICATION_FAILED로 결제된 주문이 FAILED가 될 수 있음 | 수정. 비-DONE 상태는 불일치 검사 전에 502·PENDING, attempt>0의 영구 거절은 조회 후 판단. 테스트 4건 |
| [표준] 키 형식이 코드·문서에 흩어짐 | `confirmIdempotencyKey` 헬퍼로 일원화 |
| [표준] `INVALID_RESPONSE`가 토스 코드처럼 주석됨 | 내부 코드로 명시 |

### #31 API 테스트 공백 + 녹화 복구 스캔 경합 (PR #33)
- 변이에서 살아남은 동작마다 테스트를 추가했다(위 발견 3). forward_auth 경로 조작은 `new URL`이 정규화하지 않는 `%2F` 인코딩 + DB 행 주입으로 가드 자체를 검증한다. 권한 매트릭스 대표 성공 칸은 본문까지 확인한다.
- 버그 수정: 훅이 flock을 기다리는 사이 원본이 2분을 넘기면 스캔이 Opus 원본을 먼저 등록해, 이후 훅 등록이 중복으로 끝나 크기·길이가 낡고 SSE가 안 나갔다. 훅 재등록이 기존 행의 크기·길이를 고치고 `recording`을 다시 보낸다. `segment.sh`는 flock 대기 전 빈 임시 파일(표식)을 만들고 trap으로 정리한다. 웹 `useRecordings.add`는 같은 id를 교체한다.
- API 테스트 393 → 408. e2e/12 경로 조작 확인을 원문 경로 요청(`https.request`)으로 바꿨다.
