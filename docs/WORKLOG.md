## 2026-11-09 · #5 방송 CRUD + 소유자 인가 + Soft Delete (`feat/5-broadcasts`)

### 설계 판단
| 결정 | 근거 |
|---|---|
| 상태는 `READY/LIVE/ENDED` 텍스트 + `deleted_at` | DESIGN.md §4. 전이 규칙은 #6에서 서버만 바꾼다 (API로 상태를 직접 바꿀 수 없음) |
| 목록은 `id` 내림차순 커서 페이지(`cursor`, `limit≤50`) | 오프셋은 새 방송이 생기면 중복·누락이 생긴다. 구현 비용이 같다 |
| 목록 필터는 `status`(LIVE/READY/ENDED)와 `channelId` | 이슈의 "LIVE / 전체" + 채널 화면(DESIGN §4 "채널 페이지는 사용자의 방송 목록") |
| 방송 중에도 제목·설명 수정 허용 | 방송 중 제목 변경은 실제 플랫폼에서도 흔한 사용 방식이다 |
| LIVE 삭제 409는 `UPDATE ... WHERE status != 'LIVE'` 한 문장 | 확인과 삭제 사이에 LIVE로 바뀌는 경합을 막는다 |
| 숫자가 아닌 ID는 400, 없는 방송은 404 | 공통 zod 검증 흐름을 그대로 쓴다 |
| 브라우저 E2E를 저장소에 둔다 (`e2e/`, playwright-core + 설치된 Chrome) | 화면 확인 근거를 재현할 수 있게 남긴다. 브라우저 다운로드가 없어 CI 설치 비용이 작다 |

### 코드 리뷰 (`/code-review`, 기준 dev)
| 지적 | 축 | 판단 | 근거 |
|---|---|---|---|
| `update`가 삭제된 행을 고칠 수 있고 `200 {broadcast: undefined}` 가능 | 명세·표준 | 고침 | WHERE에 `deleted_at IS NULL`, 0건이면 404 |
| `remove`가 그사이 삭제된 경우도 409로 안내 | 표준 | 고침 | 0건이면 다시 조회해 404/409 구분 |
| 목록 조건 오류가 영어 기본 메시지 | 표준 | 고침 | 모든 규칙에 한국어 메시지 (`positiveId` 헬퍼) |
| `useBroadcast`가 id가 바뀌어도 이전 결과·오류를 보여줌 | 표준 | 고침 | 결과를 id와 함께 저장해 다른 id면 무시 |
| LIVE 방송의 삭제 버튼이 활성 | 명세(사용성) | 고침 | 비활성화 + "방송을 종료한 뒤 삭제할 수 있습니다" |
| 세션 만료 후 동작하면 "로그인이 필요합니다"만 표시 | 명세(사용성) | 고침 | `useAuthErrorRedirect`: 401이면 로그인 화면 → 원래 화면 |
| 잘못된 ID·없는 채널 안내 부족, 채널 이름 미표시 | 명세(사용성) | 고침 | `GET /api/channels/:id` 추가, 안내 문구와 목록 링크 |
| 수정 화면 오류에 다음 행동 없음 | 표준 | 고침 | 404 안내 + 목록 링크 |
| 상태별 문구 분기 반복, `updatedAt` 정의 중복, `getOwned`의 미사용 컬럼 | 표준 | 고침 | 맵(`PLAYER_MESSAGE`), `nowMs` 헬퍼, 컬럼 제거 |
| 웹·API가 길이 한도(100/2000)와 상태 목록을 따로 가짐 | 표준 | 두기 | 공유 패키지를 만들 만큼 상수가 많지 않다. 서버가 최종 검증한다 |
| `{title, description}` 타입 반복 | 표준 | 두기 | 세 곳뿐이고 생성/수정의 선택 여부가 다르다 |
| 홈에서 LIVE 방송이 "전체"에도 겹쳐 보임 | 명세 | 두기 | "전체"는 말 그대로 전체다. 디자인 단계에서 섹션 구성을 다시 본다 |
